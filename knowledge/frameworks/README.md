# Cost-Tiered Autonomous Delegation

The lens Pedro applies whenever a task needs to be handed to someone or something else — an AI agent, a tool, a person — regardless of which project it's for. Assembled from three observations that look separate but optimize the same variable.

## The rule

1. **Cheapest capable tier first.** Route work to the least expensive resource that can plausibly do it, before reaching for anything more expensive. Escalate only on a demonstrated failure, not a hypothetical one. The AI-specific instance of this is the standing escalation order: opencode → Hermes → Claude Code → Opus 5 → ultracode.
2. **Full autonomy once delegated.** Whateverun it to completion on its own judgment, not pause to check in. A mid-task question back to Pedro is treated as the delegate under-performing, not as diligence.
3. **Full-scope default, not incremental confirmation.** Given a task, execute the complete, reasonable-defaultversion of it rather than presenting options one. Multi-choice clarifying questionsmid-task are a rejected pattern.

## Why this is one framework, not three preferences

All three minimize the same cost: Pedro's attention per unit of work done. Cheapest-tier-first keeps out-of-pocket/compute cost down. Full autonomy stops the delegate from bouncing decisions back up the chain. Full-scope-default stops Pedro from being asked to adjudicate something a sane default already resolves. Drop aof the three and a checkpoint reappears thatally to remove.

## When NOT to apply this

Irreversible or high-blast-radius actions — destructive data operations, anything touching shared or external systems, spending real money past a threshold — still warrant a check-in regardless of tier or autonomy defaults. Cost-tiered autonomy governs *routine* delegation; it isn't a license to skip judgment on risk. (Concretely: this is why a recursive folder delete got blocked mid-task go ahead" — that action needed sign-off from a level this framework doesn't cover.)
